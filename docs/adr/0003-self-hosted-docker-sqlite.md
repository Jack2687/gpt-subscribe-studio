# ADR 0003：容器化自托管 + SQLite 默认存储

**状态**: Accepted
**日期**: 2026-10-09

## 背景

使用者是需要「帮别人开通订阅」的运营方，诉求是**一条命令起全栈**、数据自己掌握、
默认不对外暴露。上游项目本身是本地优先（Windows 桌面 / 本地 Vite 服务）。

## 决策

1. 以 `docker compose` 作为唯一官方部署形态，默认只监听 loopback / 内网。
2. 默认存储为 **SQLite**（单文件、零运维、易备份），DSN 可切换到 PostgreSQL。
3. 任务编排先用「数据库轮询 + 单 worker 占锁」，**不引入 Redis/Celery**。
4. 公网暴露必须经过反向代理 + 鉴权，这是唯一允许的对外路径。

## 理由

- 目标规模是几百级并发任务，Redis/Celery 带来的运维复杂度不划算。
- SQLite 与「本地优先」理念一致，方便用户备份与迁移。
- 占锁机制天然满足断点续跑（进程崩溃后锁超时可被回收）。

## 被否方案

| 方案 | 否决原因 |
|---|---|
| Celery + Redis | 自托管复杂度上升，百级任务不需要 |
| 仅桌面应用（WPF） | 无法满足多用户下单与容器化自托管诉求 |
| 直接 Postgres | 对个人运营方过重，作为可选路径保留 |

## 影响

- 并发上升到千级任务时需迁移到 PostgreSQL + 独立队列，届时新增 ADR。
- `services/api/app/db.py` 是唯一 DSN 入口。
