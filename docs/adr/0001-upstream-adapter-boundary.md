# ADR 0001：上游以 adapter 边界集成，不复制无许可证代码

**状态**: Accepted
**日期**: 2026-10-09

## 背景

本平台的能力来自三个上游项目，但其中两个（`GPT-Register-Tool`、`gpt-checkout-studio`）
**没有 LICENSE 文件**，按默认著作权规则属于「保留所有权利」。直接复制其源码进本仓库会造成
侵权风险；同时它们调用的是非官方且频繁变更的内部接口，深度耦合会让维护成本失控。

## 决策

1. **不复制**上游源码进 `services/`、`packages/`、`apps/`。
2. 每项上游能力由一个 `adapter` 实现，adapter 是**唯一的**上游接触点。
3. 上游通过 `git submodule` 或环境变量指向的路径依赖接入（见 `deploy/.env.example`）。
4. adapter 必须声明 `AdapterCapabilities`：来源、许可证、支持范围、失败模式。
5. MIT 上游（`zkky`）允许在保留版权声明的前提下复用，但**仍优先走 adapter**以统一失败处理。

## 理由

- 合规：规避无许可证代码的复制风险。
- 可维护：上游接口变化只影响 adapter 层，领域模型稳定。
- 可测试：adapter 可被 `Fake*` 实现替换，实现完全离线测试。

## 被否方案

| 方案 | 否决原因 |
|---|---|
| 直接 fork 三项目合并 | 许可证风险 + 三套互不兼容的状态机 |
| 全部重写 | 成本过高，且上游协议细节难以短期复刻 |
| 只用 shell 脚本串联 | 无法表达显式状态机与断点续跑 |

## 影响

- 运行环境需额外准备上游（submodule 或路径依赖），见 `docs/upstream-integration.md`。
- 每个 adapter 需要一份失败模式清单。
